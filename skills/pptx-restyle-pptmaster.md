# Restyle PPTX через ppt-master (Open WebUI)

Механика — проект **ppt-master** (MIT, github.com/hugohe3/ppt-master), маршрут **Edit Native PPTX**: референс
импортируется в round-trip workspace, его слайды используются как скелеты, ты меняешь только текст/картинки в
компактных SVG, экспорт восстанавливает всё остальное байт-в-байт. Этот файл — только обвязка под Open WebUI;
процедуру задают документы ppt-master, их правила главнее твоих привычек.

## 0. Особенности этой среды (читать обязательно)

- **Картинки** ты видишь только через `read_file` с одним параметром `path` (без `start_line`/`end_line`).
  `display_file` показывает файл пользователю, тебе он ничего не возвращает.
- **Вложения чата не попадают в терминал.** Найди файлы одной командой `find ~ -maxdepth 3 -iname '*.pptx'`; если
  нужных нет — сразу попроси пользователя загрузить оба файла в рабочую папку через файловый менеджер Open Terminal.
- Каждый `run_command` — новый shell. Команды ppt-master запускай так:
  `source ~/.skills/ppt-master/.venv/bin/activate && python3 "$SKILL_DIR/scripts/…"` (зависимости — в этом venv).
- `SKILL_DIR` = абсолютный путь `<HOME>/.skills/ppt-master/skills/ppt-master` (узнай `<HOME>` через `echo $HOME`).
  В документах ppt-master префикс `skills/ppt-master/` заменяй на `$SKILL_DIR`.
- Рабочая папка задачи: `~/<задача>/` (или та, что назвал пользователь). Workspace ppt-master создавай внутри:
  `~/<задача>/projects/<slug>_<YYYYMMDD>`. Не работай в чужих папках других задач.

## Жёсткие запреты (нарушались на практике)

- **Никогда не собирай презентацию заново** (`Presentation()`, рисование фигур python-pptx, «чистая сборка»,
  «fresh deck»). Единственный экспортёр — `svg_to_pptx.py --roundtrip`. Если результат плохой — чини SVG.
- Не правь SVG своими скриптами с поиском по координатам и не выкидывай `data-pptx-*` атрибуты. Меняй текст внутри
  существующих `<text>`/`<tspan>` по правилам text-model из edit-native-pptx.md §5.
- `--refresh-summary` и `svg_quality_checker.py --roundtrip --json` — после КАЖДОГО круга правок и до экспорта.
  Ошибки чекера = переполнение: сократи текст до ёмкости слота (длина ≈ длине исходного текста этого слота
  референса), разбей на другой слайд или возьми скелет крупнее.
- Наложение строк в рендере почти всегда значит, что новый текст длиннее слота. Лечение — короче текст, а не
  пересборка.

## 1. Установка (если ещё нет)

```bash
D=~/.skills/ppt-master
if [ ! -d "$D/.git" ]; then git clone -q --depth 1 https://github.com/hugohe3/ppt-master "$D"; fi
[ -x "$D/.venv/bin/python3" ] || (python3 -m venv "$D/.venv" && "$D/.venv/bin/pip" install -q -r "$D/requirements.txt")
KIT=~/.skills/pptx-kit
if [ -d "$KIT/.git" ]; then git -C "$KIT" pull -q --ff-only || true; else git clone -q --depth 1 https://github.com/sergeykruglovit-a11y/owui-pptx-kit "$KIT"; fi
```
`pptx-kit` нужен только для визуального QA (§4).

## 2. Загрузка процедуры ppt-master

1. `read_file "$SKILL_DIR/SKILL.md"` и выполни его «Mandatory Load Order»: `attribution_guard.py` (через venv;
   ненулевой код — стоп), `workflows/routing.md`.
2. Маршрут для нашей задачи — **Edit Native PPTX** (референс = «raw PPTX template», исходник = «new material»).
   Прочитай `workflows/edit-native-pptx.md` и далее только то, что он требует (например,
   `references/shared-standards-core.md` перед первой правкой). Другие маршруты не загружай.
3. Материал: исходную презентацию переведи в Markdown:
   `python3 "$SKILL_DIR/scripts/source_to_md/ppt_to_md.py" "<исходник>.pptx" -o ~/<задача>/work/src_md/source.md`.

## 3. Ход работы — строго по edit-native-pptx.md

- Импорт референса (§3), план по `authoring_summary.json` (§4), посмотри рендеры слайдов референса (§4 ниже даёт
  команду рендера), чтобы понимать, что выражает каждый скелет.
- **⛔ Ворота подтверждения (§4.3)**: покажи пользователю план (выходной слайд → слайд-скелет референса →
  что туда идёт из исходника, что выброшено и почему) и **закончи ход, ожидая «ок»**. Не редактируй SVG и не
  экспортируй до подтверждения.
- После «ок»: `page_plan.json`, правки SVG, `--refresh-summary`, `svg_quality_checker.py --roundtrip`, экспорт
  `svg_to_pptx.py --roundtrip`, `pptx_delivery_check.py`, read-back — всё как в §5–7.
- Обязательные правила качества поверх ppt-master:
  - каждый слайд исходника должен быть представлен (или явно объединён/выброшен в подтверждённом плане); ключевые
    пункты — на слайде, а не в заметках;
  - первый слайд — обложка референса, последний — его финальный/контактный слайд, если они есть;
  - не больше 3 выходных слайдов подряд на одном скелете, если в референсе есть альтернативы;
  - текст, цифры, фото и скриншоты референса, не относящиеся к новому содержанию, — удалить (Slide-local); дизайн
    (лого, иконки карточек, декор, фирменное фото композиции) — оставить; удалив картинку, не оставляй пустую область;
  - пометки редактора из исходника («дописать», «уточнить») не переносить и не заменять своим текстом — вопрос
    пользователю.

## 4. Визуальный QA по рендерам (ppt-master его не делает — обязательно)

После экспорта:
```bash
cd ~/<задача> && K=~/.skills/pptx-kit/pptx_kit.py
python3 $K profile "<референс>.pptx" --out work/ref          # один раз: рендеры шаблонов
python3 $K outline "<исходник>.pptx" --out work/src          # один раз: содержание исходника
```
Запиши `work/qa_plan.json`: `{"slides": [{"template": <source_slide из page_plan>, "source": <номер слайда
исходника>}, …]}` в порядке выходных слайдов, затем:
```bash
python3 $K qa "<путь к экспорту из exports/>" --plan work/qa_plan.json --ref-dir work/ref --src-dir work/src --out work/qa
```
- `report.md`: «content: only N%» — потеряно содержание; «leftover template text» — остался текст референса
  (если это нейтральная подпись дизайна вроде «Задача», можно оставить, но осознанно).
- Открой через `read_file` КАЖДУЮ `work/qa/pair-NN.jpg` (слева скелет, справа результат): нет чужого контента,
  текст не вылезает и не налезает, нет пустых областей, иерархия как у скелета, содержание соответствует исходнику.
- Исправь SVG → refresh → checker → экспорт → qa. Максимум 3 круга, потом честно перечисли компромиссы.
- Рендеры с подменённым шрифтом (если в рендерере нет шрифта референса) могут слегка отличаться переносами.

## 5. Сдача

- Скопируй итоговый файл из `exports/` в `~/<задача>/<исходник> — в стиле <референс>.pptx`; `display_file` для него
  и для `work/qa/contact.jpg`. Ссылок `sandbox:`/`file:` не давай — путь в терминале текстом.
- Отчёт: receipt экспорта (`passthrough/patched/rebuilt`), какие скелеты использованы, что сокращено/выброшено,
  остаточные компромиссы, вопросы по пометкам редактора. «Точное соответствие» — только если QA чистый.
