# PPTX restyle по референсу (pptx-kit)

Цель: результат должен выглядеть так, будто его сверстал дизайнер референса — те же сетка, фон, лого, карточки,
шрифты и цвета, — а содержание полностью взято из исходника.

Метод один: **клонировать слайды/макеты референса и подставлять в их слоты текст исходника**.
Механику делает `pptx_kit.py`, твоя работа — план раскладки (`plan.json`) и визуальный контроль.

## Запрещено (это причины всех прошлых провалов)

- Рисовать слайды «по мотивам» с нуля (свои цвета, свои фигуры, свой формат 4:3 / 16:9).
- Класть рендеры/скриншоты слайдов референса фоном и накрывать их плашками.
- Писать собственный python-pptx скрипт вместо `pptx_kit.py build`. Если kit чего-то не умеет — скажи пользователю, какой
  функции не хватает, и предложи компромисс.
- Объявлять «готово», не посмотрев глазами каждую пару `pair-NN.jpg`. Проверка «файл открывается» — не проверка.
- Выдумывать факты/цифры, которых нет в исходнике, или молча выкидывать содержание.

## Как смотреть картинки (важно)

Картинки ты видишь ТОЛЬКО через `read_file` с одним параметром `path` (без `start_line`/`end_line`, не передавай
пустые строки и нули). `display_file` показывает файл пользователю, тебе он ничего не возвращает.

## 0. Подготовка

Создай задачи (`create_tasks`) по шагам 1–6. Рабочая папка — `~/<название задачи>/` (если её нет — создай и
скопируй туда оба файла). Все промежуточные файлы — в `work/` внутри неё.

```bash
KIT=~/.skills/pptx-kit
if [ -d "$KIT/.git" ]; then git -C "$KIT" pull -q --ff-only || true
elif [ ! -f "$KIT/pptx_kit.py" ]; then git clone -q --depth 1 https://github.com/sergeykruglovit-a11y/owui-pptx-kit "$KIT"; fi
python3 $KIT/pptx_kit.py doctor
```

**Где файлы.** Вложения чата НЕ попадают в файловую систему терминала. Ищи файлы одной командой
(`find ~ -maxdepth 3 -iname '*.pptx'`); если нужных нет — не обыскивай диск, а сразу попроси пользователя загрузить
оба файла в рабочую папку через файловый менеджер Open Terminal и назови эту папку.

Если исходник не .pptx (ppt/key/odp/pdf) — сначала `soffice --headless --convert-to pptx <файл>` (pdf так не
конвертируется: скажи пользователю).

## 1. Изучи референс

```bash
cd ~/<задача> && python3 ~/.skills/pptx-kit/pptx_kit.py profile "<референс>.pptx" --out work/ref
```

Прочитай `work/ref/profile.md` целиком. Посмотри `work/ref/contact.jpg`, затем `work/ref/render/annot-NN.png` для
каждого шаблона, который собираешься использовать (на них id фигур: синие — текст, красные — картинки, оранжевые —
сложные группы), и `render/layout-NN.png` для макетов.

Составь для себя каталог: какие типы слайдов есть (обложка, тезис, 3 карточки, список, цифры, картинка+текст…),
сколько пунктов вмещает каждый, где заголовок. Шаблоны с пометкой «слайд целиком картинка» для текста не используй.

## 2. Изучи исходник

```bash
python3 ~/.skills/pptx-kit/pptx_kit.py outline "<исходник>.pptx" --out work/src
```

Прочитай `work/src/outline.md`, посмотри `work/src/contact.jpg`. Красный текст (⚠) — пометки редактора: не переноси
их на слайд, а задай вопрос пользователю в итоговом сообщении.

## 3. План раскладки `work/plan.json`

Для каждого слайда исходника выбери шаблон референса по смыслу и количеству элементов:
- обложка → титульный шаблон; тезис/вводная → шаблон с крупным текстом; N пунктов → шаблон с N карточками/строками
  (лучше чуть больше слотов и удалить лишние, чем впихивать); цифры/KPI → шаблон с цифрами; таблица → `add` table.
- Разнообразие обязательно: не больше 3 слайдов подряд на одном шаблоне. Если подходящих «карточных» шаблонов
  мало, используй для части слайдов шаблон-список (лид + пункты), шаблон с крупным тезисом, шаблон с цифрами
  или макет (`layout`) — подача должна меняться так же, как в самом референсе.
- Сохраняй порядок и всё содержание исходника. Длинный абзац можно сократить до сути или разложить по карточкам
  (заголовок карточки + 1–2 строки), но смысл и все сущности (названия проектов, цифры) — сохранить.
- Укладывайся в `cap≈N` слота. Пункты списка с маркерами-картинками — строго в одну строку.
- Названия продуктов, скриншоты интерфейсов, фото людей из референса — это контент референса. Если фото/скриншот не
  относится к теме — удали его (`delete`), если это нейтральный декор — оставь.

Формат:
```json
{"slides": [
  {"template": 3, "source": 2,
   "fill": {
     "10": "Заголовок или строка",
     "6":  ["Абзац 1 (стиль 1-го абзаца шаблона)", "Абзац 2 (стиль 2-го)"],
     "12": {"paragraphs": ["**жирный** обычный", {"text": "подпункт", "level": 1}], "shrink": true}
   },
   "delete": [74, 99, 85],
   "respace": [["4", "75"]],
   "keep": [], "clear": [],
   "images": {"22": "work/src/img/s05_7.png"},
   "add": [{"type": "table", "into": "60", "rows": [["A","B"],["1","2"]],
            "style": {"header_fill": "#1F4E79", "header_color": "#FFFFFF", "band_fill": "#EEEEEE", "color": "#222222", "font_size": 12}},
           {"type": "image", "into": "60", "file": "work/src/img/s04_5.png", "mode": "contain"}],
   "notes": "заметки докладчика из исходника"},
  {"layout": 5, "source": 3, "fill": {"title": "…", "body": ["…"]}}
]}
```
Правила:
- Ключи `fill` — id фигур из profile.md (для `layout` — ключи плейсхолдеров `title`, `body`, `body2`…).
- Строка в `fill` делится на абзацы по `\n`; перенос строки внутри абзаца — `<br>`; `**…**` — жирный.
- Абзацы списка получают стиль соответствующего абзаца шаблона (см. «стили абзацев» в profile.md): в карточке
  «заголовок + описание» передавай `["Заголовок", "Описание"]`.
- Незаполненные текстовые фигуры шаблона удаляются автоматически (чтобы не осталось чужого текста). `[chrome]`
  (лого, колонтитулы, номера) сохраняются всегда. Нужно оставить текст шаблона как есть — `keep`.
- Убираешь карточку целиком — удали её SHAPE и всё из «содержит: …» (`delete`), затем растяни оставшиеся
  карточки ряда: `respace`.
- Цвета для `add` table бери только из палитры profile.md.
- Первый слайд — титульный шаблон референса (обложка), последний — финальный/контактный, если они есть. Не
  влезает заголовок — сократи его или `shrink`, но не заменяй обложку контентным слайдом.
- Заметки докладчика (`notes`) — только для заметок из исходника. Содержание слайда в заметки не переносится:
  ключевые пункты должны быть на слайде (на разделителе без места — выбери другой шаблон).
- Не добавляй свою нумерацию/маркеры («1.», «•») в слоты, где шаблон уже даёт маркеры.

## 4. Сборка

```bash
python3 ~/.skills/pptx-kit/pptx_kit.py build "<референс>.pptx" work/plan.json --out "<исходник> — в стиле <референс>.pptx"
```
Каждый `WARN` — реальная проблема: сократи текст / выбери другой шаблон / `shrink`, пересобери.

## 5. QA — обязательно, до 3 итераций

```bash
python3 ~/.skills/pptx-kit/pptx_kit.py qa "<результат>.pptx" --plan work/plan.json --ref-dir work/ref --src-dir work/src --out work/qa
```
1. Прочитай `work/qa/report.md`, исправь все пункты. «content: only N%» — на слайде потеряно содержание исходника
   (в `plan.json` у каждого слайда должен быть `"source": <номер слайда исходника>`).
2. Открой через `read_file` КАЖДУЮ `work/qa/pair-NN.jpg` (слева шаблон, справа результат) и проверь:
   - нет чужого текста/картинок референса, в том числе текста внутри картинок;
   - текст не вылезает из карточек и не налезает на другие элементы, нет пустых карточек, маркеров без текста;
   - баланс: нет больших пустых областей там, где в шаблоне был контент (иначе другой шаблон или `respace`);
   - иерархия как в шаблоне: заголовок там же и того же стиля;
   - содержание слайда соответствует исходнику.
3. Исправь plan.json → build → qa. Повтори, пока пары не станут чистыми (максимум 3 круга; дальше перечисли
   оставшиеся компромиссы пользователю).

Если в profile.md есть «⚠ Нет в рендерере» — рендеры показывают подменённый шрифт (обычно шире оригинала).
Небольшие переносы в рендере допустимы, но явное переполнение исправляй. Скажи пользователю, что в PowerPoint с
установленным шрифтом вёрстка будет точнее, и что шрифт можно положить в `~/.fonts` (затем `fc-cache -f`).

## 6. Сдача

- `display_file` для итогового .pptx и для `work/qa/contact.jpg` (не давай ссылок `sandbox:` / `file:` — в чате они
  не открываются; путь в терминале укажи текстом).
- Короткий отчёт: сколько слайдов, какие шаблоны использованы, что сокращено/объединено, какие компромиссы
  остались, вопросы по пометкам редактора. Не пиши «точное соответствие», если были компромиссы.
